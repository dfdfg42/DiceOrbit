# 설명 글 쓰는 법 (2026-10-05)

게임 안의 설명 글은 전부 같은 형식이다. 몬스터 기술 설명을 말풍선 옆 칩에 띄우려고 간결하게 줄인 것이 시작이고
(`battle_visual_language.md` 「몬스터 의도 설명」), 같은 형식을 나머지 설명 전부에 적용했다.

## 형식

- **한두 줄.** 첫 줄 = 무슨 일이 일어나나. 둘째 줄 = 조건·부연. 짧으면 한 줄에 "조건 + 결과"로 써도 된다.
- **명사형으로 끝낸다.** "~합니다 / ~하세요" 없이 "피해 20", "이동 불가", "발동 후 사라짐". 마침표를 찍지 않는다.
- **수치는 기호로.** "25% 증가" → `+25%`, "10 감소" → `-10`, "방어도 5를 얻습니다" → `방어도 +5`.
- **가운뎃점(·)** 으로 한 줄 안의 두 사실을 잇는다: "밟으면 피해 12 · 터지면 사라짐".
- **한 줄은 28자 안쪽.** 전투 정보 패널(폭 약 370)에 한 줄로 들어가는 길이다. 넘으면 낱말 중간에서 꺾인다("현재 구/역 1명").
  타일 패널은 더 좁아서 22자 안쪽이 안전하다. 몬스터 기술(칩)은 20자.
- **수치는 설정값에서 넣는다.** 코드가 만드는 글은 `{Value}`·`{percent}` 같은 필드를 그대로 꽂는다 — 숫자를 글에 박아 두면 밸런스를 바꿀 때 어긋난다.

### 낱말

| 낱말 | 뜻 |
|---|---|
| 밟으면 | 지나가거나 그 칸에 도착할 때 (`OnTraverse`). 턴 종료에도 발동하는 타일도 이 말을 쓴다 |
| 여기서 턴을 마치면 | 그 칸에서 턴을 끝낼 때만 (`OnEndTurn`) |
| 지나가면 | 통과만 해도 (불꽃 끄기처럼 '밟기'와 구분해야 할 때만) |
| 1명 / 한 명 | 대상 하나. 구역 = 몬스터 구역(부채꼴) |
| 칸 | 궤도 타일 하나 |

### 보기

| 종류 | 글 |
|---|---|
| 몬스터 기술 | `{피해} 피해 · 대상 좌우 2칸` / `{피해} 피해 · 1명`⏎`피해 15 이상 주면 취소` |
| 콤보 단계 | `[지진파] 공격력 110% 피해`⏎`현재·양옆 구역 전부` |
| 캐릭터 패시브 | `도적의 공격 피해 +30%`⏎`같은 구역의 다른 아군 1명당` |
| 타일 | `밟으면 1턴 동안 이동 -2칸`⏎`발동 후 사라짐` |
| 모디파이어 | `공격 피해 +10%`⏎`같은 구역에 다른 아군이 있을 때` |
| 주사위 효과 | `사용 시 방어도 +5` |
| 포션 | `적 1명에게 쇠약 2턴`⏎`주는 피해 -25%` |
| 키워드 | `다음 자동공격 피해 +25%`⏎`행동 한 번에 적용 후 사라짐` |
| 이벤트 결과 | `골드 +50` · `모든 아군이 최대 체력의 20% 회복` (한 줄 — 여러 결과가 " · "로 이어진다) |

## 글이 사는 곳

| 설명 | 어디에 쓰나 | 어디에 뜨나 |
|---|---|---|
| 몬스터 기술 | 몬스터 프리셋의 기술 `description` (인스펙터). `{피해}`는 예상 피해로 바뀐다 | 말풍선 옆 칩·행동 말풍선·정보 패널 (`MonsterIntentText`) |
| 몬스터 패시브 | 수치가 든 것은 `GetDynamicDescription()` (또는 `Description` 재정의), 아니면 프리셋의 `description` | 정보 패널 (동적 글이 있으면 그것만) |
| 캐릭터 콤보 | `ComboActiveSkill.GetStageDescription(stage)` — 첫 줄 "[이름] 피해", 둘째 줄 "누구에게 + 덤" | 정보 패널(지금 단계) |
| 캐릭터 스킬 요약 | `GetSelectionSummary()` — 첫 줄 "조건 연속 → 3단계 콤보", 둘째 줄 "1단계 → 2단계 → 3단계" | 모집 화면 |
| 캐릭터 패시브 | `GetDynamicDescription()` | 모집 화면·정보 패널 |
| 타일 속성 | `TileAttribute.GetDescription()` 재정의. 지속 시간은 패널 제목 줄이 따로 보여 주니 글에 넣지 않는다 | 타일 패널 |
| 모디파이어 | `CharacterModifier.Description` (첫 줄 = 효과, 둘째 줄 = 조건) | 보상 카드·정보 패널·상점 |
| 주사위 효과 | `DieEffect.Preview()` (한 줄, "사용 시 …") | 주사위 툴팁·보상 카드·이벤트 선택지 |
| 포션 | 포션 에셋 `Description` | 런 HUD 툴팁·상점·보상 |
| 유물 | 유물 에셋 `artifactTooltip` | 런 HUD 툴팁·상점·보상 |
| 키워드(상태이상 포함) | `Resources/UI/TooltipKeywordDatabase.asset` | 키워드 링크 툴팁·상태 아이콘 툴팁 |
| 이벤트 결과 | `EventOutcome.Preview()` (한 줄) | 이벤트 선택지 |

안내문(“동료를 고르세요”, “대상 몬스터를 클릭하세요”)과 결과 알림(“전리품을 챙겼습니다”)은 설명이 아니라 말 거는 글이라 문장형 그대로 둔다.

## 검사

- 메뉴 **DiceOrbit → Run Description Style Self-Tests** (`Editor/DescriptionStyleSelfTests.cs`) — 캐릭터 스킬·패시브, 몬스터 패시브·사망 효과,
  포션, 유물, 키워드, 모디파이어, 주사위 효과를 훑어 빈 설명·3줄 이상·한 줄 28자 초과(모집 요약은 36자)·문장형("~니다", "~세요")·마침표를 잡는다.
- 메뉴 **DiceOrbit → Run Monster Intent Self-Tests** — 몬스터 기술(칩) 전용: 2줄·줄당 20자·`{피해}`와 예상 피해의 짝.
- 타일 속성과 이벤트 결과는 생성자 인자가 필요해 자동으로 훑지 못한다 — 새로 쓸 때 위 형식을 손으로 맞춘다.

## 새 글을 쓸 때

1. 위 표에서 그 설명이 사는 곳을 찾아 같은 형식으로 쓴다. 수치는 필드에서 꽂는다.
2. 기술·패시브 클래스의 생성자 기본 설명도 같은 형식으로 둔다 (인스펙터에서 새 인스턴스를 만들면 그 글이 들어간다).
3. 자가 테스트 두 개를 돌린다.
