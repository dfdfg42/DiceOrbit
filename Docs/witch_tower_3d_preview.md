# 마녀의 탑 — 3D 전투방 시안

2026-10-18 프리뷰 제작, 2026-10-19 승인된 배경을 본편 BattleScene에 적용.

## 방향

기존 `Assets/Sprites/배경/배경 수정 1차.png`와 `임시배경1.png`를 참고한다.
사용자 요청은 아기자기한 마녀의 탑 원형 방이며, 원형 타일과 몬스터 영역 표시를 고려한 배치다.
둥근 돌벽, 크림색 기둥, 파란 아치 창문, 물약장·책장·책상·수정구·작은 가마솥을 직접 만든 메시로 구성한다.

## 열기

- 본편 씬: `Assets/Scenes/BattleScene.unity` — 기존 메인메뉴·모집·맵 선택 흐름으로 전투에 진입한다.
- 별도 시연 씬: `Assets/Scenes/WitchTowerPreview.unity`
- 방 프리팹: `Assets/Art/WitchTower/WitchTowerRoom.prefab`
- 생성 도구: `DiceOrbit > Witch Tower > Build Preview Scene`
- 프리뷰 씬을 열어 Play하면 네 캐릭터와 네 몬스터로 예시 전투를 시작한다.
- 본편에는 방 프리팹·조명·영역 재질을 적용하고 기존 2D 배경 오브젝트를 비활성화한다. 빌드 씬 목록은 이미 BattleScene을 사용하므로 변경하지 않는다.
- 프리뷰는 RunManager.StartRun을 호출하지 않고, 보유 세이브를 로드하거나 신규 런을 저장하지 않는다.
  전투 UI 초기화 뒤 GameFlowManager 컴포넌트를 분리하므로 승패가 본편 보상/게임오버 저장 처리로 넘어가지 않는다.
  재시작은 Play를 종료하고 다시 시작한다.

## 전투 표시와 배치

원본 BattleScene의 카메라, 반지름 13 / 20칸 궤도, 반지름 7의 몬스터 배치와 실제 ZonePlateRenderer를 사용한다.
네 구역의 색과 경계는 기존 전투 시스템이 그린다. 방 바닥에 별도의 사분면이나 소유 색을 넣지 않는다.

- 영역 플레이트 y = -0.02. 중앙 바닥 윗면 y = -0.16으로 분리한다.
- 바닥 재질은 깊이 버퍼를 쓰지 않아 y=0에 걸쳐 있는 기존 빌보드 몬스터 하단을 자르지 않는다.
- 중앙 바닥은 반지름 17까지 단색에 가깝게 둔다.
- 장식 바닥과 외곽 통로는 반지름 17 바깥에 배치한다.
- 높은 가구는 뒤와 양옆, 앞쪽은 낮은 책과 방석으로 구성한다.
- 장식에는 콜라이더를 추가하지 않아 타일/유닛 클릭을 가로채지 않는다.

## 편집과 재생성

프리팹의 `01`은 바닥, `02`는 벽과 창문, `03`은 가구다. 개별 오브젝트 위치·크기·재질을 편집할 수 있다.
메시와 재질은 `Assets/Art/WitchTower/Meshes`, `Materials`에 저장되어 생성 도구 없이도 표시된다.
재생성 메뉴는 해당 프리팹·재질·메시와 프리뷰 씬을 다시 작성한다. 손으로 조정한 버전을 보존하려면 먼저 별도 이름으로 복제한다.
본편도 이 방 프리팹과 재질을 공유한다. `Apply Approved Room to Battle Scene` 메뉴는 본편에 방을 한 개만 배치하고 조명·영역 설정을 연결한다. 프리뷰 재생성도 기존 방 인스턴스를 먼저 제거하여 방이 중복되지 않는다.

## 자동 확인

Unity 에디터의 `DiceOrbit.EditorTools.WitchTowerRoomBuilder.BuildAndCapture`를 배치 실행하면
프리뷰 생성 → Play 진입 → 첫 플레이어 턴 대기 → 실제 카메라와 방 전체 카메라 렌더를 수행한다.
현재 결과는 `_workspace/2026-10-18-witch-tower/zones/`에 저장한다. `windows/`는 창문 디테일, `brick/`는 벽돌색 복원, `idle/`는 대기 애니메이션 추가, `props/`는 소품 추가, `polish/`는 재질 패스, 상위 폴더는 첫 조형 시안의 렌더다.
이 렌더는 월드와 전투 유닛 확인용이며 화면 공간 Overlay HUD는 포함하지 않는다.

## 두 번째 패스 — 손그림 캐릭터와 재질 맞추기

- `WitchTowerPaint.shader`: 보라색 그림자와 따뜻한 밝은 면을 부드러운 명암 단계로 표현한다. 반짝이는 플라스틱 하이라이트 대신 물감의 색 변화와 약한 나뭇결을 사용한다.
- `WitchTowerPaper.hlsl`: 월드 좌표에 고정된 절차적 안료 질감. 화면에서 작아지는 미세 질감은 미분값으로 감쇠해 움직일 때 깜빡임을 줄인다.
- `WitchTowerInk.shader`: 가구·병·책·기둥의 외곽에 짙은 보라색 선을 넣는다. 벽돌과 바닥에는 적용하지 않는다.
- 외곽선은 메시의 겹치는 정점을 기준으로 평균 낸 법선으로 확장하며, 본체 메시의 평면적인 명암은 유지한다.
- 바닥은 기존 깊이 처리와 렌더 순서를 유지하고 중앙의 안료 질감 강도를 외곽보다 낮춘다.
- `room-detail.png`는 물약장과 창문 주변을 가까이서 확인하는 렌더다.

## 세 번째 패스 — 소품 형태 정리와 추가

- 포션 앞면의 라벨·별 문양·붙인 광택 장식을 없애고, 선반 높이에 맞춰 병 크기를 줄인다.
- 화분은 속이 파인 도기와 흙, 연결된 줄기와 입체 잎으로 구성한다. 기존 꽃 장식을 제거한다.
- 빗자루 두 개, 책상 위 펼친 두루마리, 두루마리 바구니, 버섯 화분 두 개, 절구와 공이가 놓인 약초 작업대를 추가한다.
- 모든 새 소품은 반지름 17 바깥 통로에 배치한다. `new-props.png`에서 오른쪽 소품을 가까이 확인할 수 있다.
- Unity 배치 Play 확인: 타일 20개, 몬스터 4마리, 파티 4명으로 첫 플레이어 턴에 도달했다. 컴파일 오류·셰이더 오류·런타임 예외는 없었다.

## 네 번째 패스 — 제본 디테일과 기본 대기 동작

- 책장에는 두께·높이·깊이가 다른 책 18권을 배치한다. 각각 페이지 블록, 양쪽 표지, 둥근 책등, 제본 띠, 얇은 금박선을 별도 메시로 만든다. 일부 책에는 책갈피가 달린다.
- 눕힌 책에도 페이지 층, 책등 제본과 책갈피를 추가한다. 가는 페이지 선에는 외곽선을 중복 적용하지 않고 책과 잎은 얇은 전용 외곽선을 쓴다.
- `WitchTowerIdleMotion`은 프리팹에 저장되어 Play하면 자동 실행된다. 별도 Animator나 애니메이션 클립 연결은 필요 없다.
- 촛불은 심지에서 일렁이고, 가마솥 기포는 수면에서 올라가며 작아져 사라진다. 수정구는 살짝 떠오르고, 잎·버섯·깃발·빗자루·책갈피는 각자의 뿌리나 고정점에서 움직인다.
- 포션은 약한 팽창, 책장 책은 작은 앞뒤 움직임, 두루마리는 가벼운 흔들림, 공이는 절구 안에서 작은 회전 동작을 사용한다. 책장·책상·벽·전투 바닥은 고정한다.
- Inspector의 `Period`, `Position/Rotation/Scale Amplitude`로 각 움직임을 조절한다. 컴포넌트를 끄면 원래 위치·회전·크기로 돌아간다. `Time.timeScale = 0`이면 대기 동작도 정지한다.
- 실제 Play 중 72프레임을 캡처하고 87개 대기 동작 대상 모두의 로컬 자세가 바뀌었음을 확인했다. 첫 플레이어 턴에서 타일 20개·몬스터 4마리·파티 4명을 확인했으며, 컴파일·셰이더 오류와 런타임 예외는 없었다.
- `bookshelf-detail.png`는 책장 확대, `frames/`는 대기 동작의 연속 렌더다. 같은 폴더의 `make_preview.py`로 실제 프레임 간격을 보존한 `room-idle.gif`를 묶는다.

## 다섯 번째 패스 — 첫 3D 시안의 따뜻한 벽돌색 복원

사용자가 지정한 기준은 `_workspace/2026-10-18-witch-tower/battle-camera.png`다. 벽과 기둥의 따뜻한 자주·갈색 및 입체적인 음영을 이 이미지에 맞춘다.

- 벽돌·기둥·몰딩에는 첫 시안에서 사용한 URP Lit 조명 반응을 복원한다. 최신 책 디테일, 소품, 대기 애니메이션은 유지한다.
- 벽의 줄눈은 깊이를 기록하는 별도 `WallMortar` 재질을 쓴다. 게임 유닛과 겹치는 바닥의 깊이 처리와 분리한다.
- 물감 재질 소품에 불투명 그림자 패스를 추가해 가구 실루엣이 벽에 그림자를 드리우도록 한다. 외곽선 메시 자체는 그림자를 만들지 않는다.

## 여섯 번째 패스 — 창문 구조와 색유리

- 평평한 아치 테두리를 9개 아치 돌과 양옆의 돌 블록으로 바꾼다. 꼭대기 쐐기돌, 튀어나온 창턱과 아래 받침을 추가한다.
- 유리는 돌 테두리보다 뒤에 두고, 깊이가 있는 목재 창틀과 아치 안쪽 면으로 들어간 느낌을 만든다.
- 아래쪽은 네 장의 푸른색·청록색·연보라색 유리, 위쪽은 네 구획의 부채꼴 색유리로 나눈다. 가는 창살과 작은 마름모 유리 장식을 넣는다.
- 아치 중앙에는 황동 테두리와 실제 초승달 모양 메시로 만든 메달 장식을 배치한다. 외부 이미지 텍스처 없이 편집 가능한 메시로 구성한다.
- `window-detail.png`는 창문 확대, `battle-camera.png`는 실제 전투 카메라에서의 결과다.

## 일곱 번째 패스 — 바닥과 어울리는 몬스터 영역

- `WitchTowerZone.shader`는 기존 영역 스프라이트의 실루엣을 사용하면서 굵은 검은 테두리·점 무늬·번짐을 제거한다. 바닥색과 소유 몬스터의 색을 섞은 돌 표면, 얇은 줄눈, 은은한 황동 테두리와 원형 각인을 그린다.
- `ZonePlateRenderer.PlateMaterial`은 선택적인 씬별 재질이다. 이 프리뷰 씬에만 새 재질을 지정한다. 비어 있는 기존 씬은 원래 표현을 유지한다.
- 영역의 회전·모양·소유권·등장 페이드와 타일 판정은 기존 시스템을 사용한다. 중립 상태도 기존 중립색과 알파를 따른다.
- 패시브 영역 밝힘은 해당 플레이트의 재질을 공유하여 강조 중에 예전의 두꺼운 테두리가 다시 나타나지 않게 한다. 패시브 테두리와 조준 표시는 기존 규칙을 따른다.
- 배치 캡처는 `ZonePlateSelfTests`, `PassiveZoneSelfTests`를 실행하고 실제 전투에서 중립화·소유자 재배정·패시브 테두리 및 재질 연결을 검사한다. 검사 후 원래 소유권을 복원한다.
- `battle-camera.png`는 기본 상태, `battle-neutral.png`는 중립 상태 검사, `battle-passive.png`는 전사 패시브 영역 표시다.

## 여덟 번째 패스 — 타일 모서리까지 덮는 영역 범위

- 기존 스프라이트의 밝은 내부만 추출하면 바깥 테두리뿐 아니라 구역 경계 옆 타일의 안쪽 모서리도 영역 밖으로 나온다. 프리뷰 전용 셰이더의 윤곽을 둥근 모서리의 원형 부채꼴로 바꾼다.
- 실제 타일 모서리의 최대 반지름은 15.486이다. 영역 반지름은 16.35로 늘리고, 구역 사이 틈은 총 0.20으로 줄인다. 반지름 17인 전투 바닥 안에 들어간다. 중심 구멍은 반지름 2.65다.
- `PlateScale`은 기본값 1이며 프리뷰에서만 1.05로 설정해 새 윤곽을 그릴 공간을 확보한다. 패시브 밝힘도 같은 크기를 사용한다. 소유권과 타일 판정은 바꾸지 않는다.
- 실제 셰이더를 위에서 렌더한 알파를 읽어 20개 타일의 80개 모서리 주변 0.06 여유를 640개 표본으로 검사했다. 모두 자기 영역 안에 들어간다. 기존 영역 테스트, 중립·소유자 교체·패시브 표시 검사 및 87개 대기 동작 검사도 통과했다.
- 결과는 `_workspace/2026-10-18-witch-tower/coverage/battle-camera.png`, 검사 로그는 `Logs/witch-tower-coverage.log`다.

## 본편 적용 — 2026-10-19

- `BattleScene`은 승인된 방 프리팹을 직접 참조하며 프리뷰 자동 스폰 컴포넌트를 포함하지 않는다. 기존 게임 흐름과 막·몬스터 선택 설정을 사용한다.
- `WitchTowerBattleIntegrationChecks.ApplyAndCapture`는 저장된 씬을 다시 열어 구성과 빌드 등록을 검사한 뒤, MainMenu에서 BattleScene으로 전환하고 실제 맵 노드 선택 경로로 전투를 시작한다. 검사에서만 두 캐릭터를 준비하며 본편 씬에 검사 오브젝트를 저장하지 않는다.
- 검사는 영역 모서리 GPU 알파, 본편 GameFlow 유지, 방 중복 및 프리뷰 컴포넌트 부재, 런 저장 파일의 변경 여부를 확인한다. 결과 이미지는 `_workspace/2026-10-18-witch-tower/production/battle-camera.png`다.
- 실제 검증 결과: 본편 첫 플레이어 턴에 파티 2명·노드 몬스터 3마리·타일 20개, 방 1개와 대기 동작 컴포넌트 87개를 확인했다. 영역 GPU 표본 640개와 기존 영역 테스트가 통과했고, 컴파일·셰이더 오류 및 런타임 예외는 0건이었다. 저장 파일 해시도 동일했다 (`Logs/witch-tower-production.log`).

원화의 모든 선·소품을 복제한 최종 아트는 아니다. 최종 성능 최적화는 후속 작업이다.
